What this demo proves

Switch the policy to fixed and run the replay: Search returns [], the evidence gate is skipped, POST /book is still called, and the fixture answers 422 NO_ITINERARY — yet the final message claims Flight booked. Switch back to agent: the same empty result sets needs_replan, the query changes to flexible:true, the gate passes, and the run books exactly once. With every search returns [], the agent blocks with SEARCH_EMPTY and never calls the booking tool.

The controls

Features and what they prove

01

Policy toggle

Replays the same request and fixtures through the one-pass script and the agent control loop side by side.

Proves
the difference is the control plane, not the model.
Key detail
fixed logs gate skipped before POST /book.
02

Flight-strip fan-out

Search, Calendar, and Weather light up as one parallel wave, then merge into a single evidence snapshot.

Proves
independent evidence tools run concurrently and merge once.
Key detail
the gate waits for all three — booking never fires mid-wave.
03

Empty-evidence stamp

The search rail turns coral when the observation is []; the amber re-plan strip loops back with a changed query.

Proves
empty evidence is a state that triggers a new request, not a blind retry.
Key detail
attempt 2 is flexible:true, not the same query again.
04

Evidence gate

The mint booking strip crosses only when itinerary, calendarReady, and weatherLoaded are all true.

Proves
side effects are gated on explicit evidence, not on the final answer.
Key detail
the gate is evaluated after the merge, before POST /book.
05

Trace + retry budget

The trace records plan, fan-out, merge, decide, re-plan, booking, and the answer, with MAX_RETRIES = 2 enforced.

Proves
every transition is inspectable and the loop is bounded.
Key detail
with both searches empty the run ends blocked and the booking tool is never called.
